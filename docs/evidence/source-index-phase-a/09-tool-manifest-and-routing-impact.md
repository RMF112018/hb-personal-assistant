# 09 — Tool-manifest & routing impact

Summarizes every change to the client-visible MCP tool surface across Phase A and confirms the semantic
checksum was regenerated canonically (never hand-edited). Full detail: `11-manifest-semantic-diff.md`
(A2 semantic diff + regeneration) and `14-a2-corrective2-watcher-and-read-contract.md`.

## Changes to the tool surface (A2)

1. **`assistant_source_file_read` canonical `purpose` corrected** (`obsidian_mcp/tool_entry_manifest.py`) —
   from the generic family fallback `"Indexed NAS source-file discovery."` to an accurate contract:
   *bounded excerpt from one trusted indexed file; not complete-file retrieval; requires a safe root and an
   exact selected file; excerpt may be truncated or fall back to the indexed excerpt.* Added `use_when`,
   `do_not_use_when`, `examples`, `common_failure_modes`. This is the intended, correctness-driven change.
2. **`assistant_get_source` docstring clarification** (`nas_mcp/tool_registration.py`) — a 5-line docstring
   edit only; does **not** move the semantic checksum (the checksum derives from each tool's canonical
   `purpose`, and `assistant_get_source`'s purpose was already accurate).

## Checksum regeneration (canonical, not hand-edited)

The `semantic_surface_checksum` was regenerated by building the manifest through the repository's official
path (`build_manifest(...)` via `docs/evidence/source-index-phase-a/manifest_probe.py`, run with a pinned
`runtime_commit` and fixed timestamp for reproducibility), inspecting the semantic diff, and updating the
frozen artifact + `tests/test_tool_manifest_freshness_guard.py` baseline. No expected checksum was edited
merely to satisfy a guard. Raw before/after checksums: `manifest-checksum-originmain.txt`,
`manifest-checksum-a2head.txt`, `manifest-checksum-a2corrective2.txt`.

## Direct / gateway parity

`test_manifest_schema_parity.py` and `test_n8c23_client_tool_manifest.py` confirm the direct and gateway tool
surfaces remain identical after the change. Tool **names** are unchanged; no tool was added or removed.

## A4 routing impact — none (deliberately)

A4 adds **no** tool-surface change. Quarantine operations are local operator CLI commands only
(`cli/source_watch.py`: `quarantine-list`, `quarantine-inspect`, `quarantine-retry`). There is no
`@mcp.tool()` for quarantine and no gateway allowlist entry — asserted by
`test_source_index_quarantine.py::test_no_remote_quarantine_write_tool_exposed` and confirmed by the
independent branch-diff audit (`docs/evidence/source-index-phase-a/final-runs/` audit summary in `15`).

## Serving-envelope contract (A2, consumed by A4 lifecycle)

Search/list/read now return deterministic fail-closed envelopes for an unsafe root (`status` ∈
`ok | blocked_root_unready | unknown_root | unauthorized_root | invalid_request`; `authoritative:false`;
embedded sanitized `root_readiness`). The legacy misleading `read_status:"live_readable"` was replaced by
`read_status:"read_capability_known"` + explicit `live_readability`/`live_read_performed`/`authoritative`
fields (no contradictory claim survives). `test_source_index_quarantine_lifecycle.py` exercises these
envelopes end-to-end when a quarantine blocks and then clears the root.
