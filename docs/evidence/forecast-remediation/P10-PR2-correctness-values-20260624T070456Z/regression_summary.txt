Root cause: SQLiteMigrator.apply() (store/migrator.py) leaked two WAL get_connection()
connections (never closed; contract = caller closes). A leaked WAL connection checkpoints its
-wal into the main DB file only on Python GC; the new tests shifted GC timing so a benign
checkpoint landed during phase17's read-only _run, changing db.read_bytes() (no new data —
read-only intent intact). Surfaced, not caused, by the additive tests.

Fix: apply() reads MAX(version) on the existing connection and closes it before returning
(both leaks removed; WAL checkpoint deterministic). Canary passes without modifying the canary.
