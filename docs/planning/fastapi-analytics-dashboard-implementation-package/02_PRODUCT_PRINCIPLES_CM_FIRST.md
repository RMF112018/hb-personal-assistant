# Product Principles — Construction Management First

## Low-Friction Assistant UX

The UI must feel like the app is doing the work for the user. It should not require the user to maintain the system manually or understand the sync engine.

## Default Landing

Default landing should be Today, or the user's selected default view. Today should present meetings, action items, daily brief, recent changes, aging decisions, cost/change exposure, correspondence worth reading, document changes, vendor attention items, billing/cash signals, and closeout readiness.

## Construction Language

Use user-facing labels like:

- Prepare Meeting
- Review Attention Items
- Refresh Project
- Update Connection
- Schedule First Sync
- Mark Reviewed
- Review Cost Exposure
- Open Supporting Records

Avoid labels like:

- Execute
- Apply
- Dry-run
- MCP call
- Dispatch workflow
- Vector readiness
- Endpoint coverage

## Admin as Support Layer

Admin / Data Confidence is necessary but secondary. It should not dominate the default navigation or visual hierarchy.

## Advisory Guardrails

Metrics and brief content may identify signals, exposure, aging, or review-required conditions. They must not make legal, claim, entitlement, payment, schedule-delay, safety, or final financial determinations.
